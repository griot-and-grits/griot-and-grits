# Griot & Grits – Family Preservation File Workflow

## Overview

**Griot & Grits** enables families to securely **preserve, view, and update their family history** using an AI-assisted, privacy-first workflow.  
All data is processed locally or in-memory and **never stored in the cloud** unless the user explicitly chooses to do so.

---

## How It Works

### Phase 1: User Wants to Preserve

1. **Upload Unstructured Files**
    - User uploads any unstructured family history files (documents, photos, notes, etc.) to the Griot & Grits website or a self-hosted instance.
2. **AI-Powered Structuring**
    - The system uses an LLM (Large Language Model) to transcribe and organize the content.
3. **Encrypted Object File Creation**
    - An encrypted family object file is generated, containing all structured data.
    - **Privacy-first:** The file is **never stored to the cloud**. The user downloads and saves the file locally.

---

### Phase 2: User Wants to View/Query

1. **Upload Family Object File**
    - User uploads their saved family object file to the website or self-hosted version.
2. **Authentication**
    - User answers security questions to decrypt the file.
3. **View Data**
    - User views structured family data (e.g., family tree) generated by the LLM.
    - Other structured data is available for LLM-based querying (e.g., RAG, Q&A).
    - **No persistent storage:** Data remains private and under user control.

---

### Phase 3: User Wants to Update

1. **Upload Existing Family Object File**
    - User uploads their family object file.
2. **Authentication**
    - User answers security questions.
3. **Add New Content**
    - User uploads new unstructured family history content.
4. **Re-index and Update**
    - The system re-indexes and updates the file with the new information, using the LLM.
    - A **new version** of the family object file is generated and downloaded by the user.
    - Users can store this new file locally or share it with family.

---

## Security & Privacy

- **End-to-End Privacy:** Files are processed in-memory. Only the user retains their family object file.
- **Encryption:** All object files are encrypted and protected by user-set security questions.
- **User Control:** No data is stored on servers or in the cloud without user action.

---

## Typical Use Cases

- Securely digitize, structure, and preserve family archives, stories, and records.
- Visualize or query family trees and relationships.
- Incrementally update family records, maintaining privacy and versioning.
